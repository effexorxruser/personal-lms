# Резервное копирование и восстановление

## Что сохранять

| Компонент | Путь по умолчанию | Комментарий |
|-----------|-------------------|-------------|
| База SQLite | `instance/personal_lms.db` (или из `PERSONAL_LMS_DATABASE_URL`) | Состояние прогресса, пользователи, журнал терминала и др. |
| Контент курсов | `content/` | Источник уроков и заданий; без него приложение не сможет отдать материалы. |
| Конфигурация | `.env` | Секреты и флаги; храните копию вне репозитория. |

Код приложения можно восстановить из Git; для точного отката фиксируйте тег или коммит релиза.

## Резервная копия

1. Остановите сервис (`systemctl stop personal-lms` или аналог), чтобы избежать повреждения SQLite при копировании файла, **или** используйте `sqlite3 .backup`, если сервис должен оставаться запущенным.
2. Скопируйте каталог `instance/`, `content/` и зашифрованную копию `.env` в надёжное хранилище.

Пример (при остановленном сервисе):

```bash
tar -czf personal-lms-backup-$(date +%Y%m%d).tar.gz instance content
```

## Восстановление

1. Разверните ту же версию кода, что и при бэкапе (или совместимую по миграциям Alembic).
2. Распакуйте `instance/` и `content/` на место.
3. Восстановите `.env`, выполните `alembic upgrade head` при необходимости согласно цепочке миграций между версиями.
4. Запустите приложение и проверьте `/health`, вход тестового пользователя, открытие урока.

## Откат деплоя

1. Остановите сервис.
2. Верните предыдущий коммит/тег и виртуальное окружение (зависимости).
3. При откате **схемы** БД миграции Alembic должны быть согласованы вручную; для MVP чаще проще восстановить файл БД из снимка, сделанного перед обновлением.

См. также [VPS_DEPLOYMENT.md](VPS_DEPLOYMENT.md) и [ENVIRONMENT_CONFIGURATION.md](ENVIRONMENT_CONFIGURATION.md).
